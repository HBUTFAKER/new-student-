# 0.1 功能拆解 · 用户故事 · MVP 边界

> 对应《学生信息管理系统_分步执行清单》步骤 0.1。
> 本文档回答三个问题：系统有哪些功能域、每个功能给谁用什么场景、一期（MVP）做到哪条线。

## 1. 功能拆解（业务域 → 子功能 → 主要角色）

| # | 业务域 | 子功能 | 主要角色 |
|---|--------|--------|----------|
| 1 | 档案域 | 学生档案、家长档案、家长-学生多对多绑定、老师档案、教室档案 | 教务 |
| 2 | 课程域 | 课程定义、班级（关联老师/教室/时间）、课时包（套餐） | 教务 |
| 3 | 课时账本域 | 只增流水（购入/消耗/调整/退费）、余额快照 | 教务（账本本身对全系统） |
| 4 | 排课域 | 规律排课（每周固定）、单次调整、冲突校验（老师/教室/学生）、补课排期 | 教务 |
| 5 | 签到域 | 课堂点名签到、扣课时（同事务+幂等）、缺勤扣课规则配置 | 老师、教务 |
| 6 | 交易域 | 缴费登记、退费、转班、补课 | 教务 |
| 7 | 报表域 | 出勤率、课时消耗、营收、续费预警 | 机构管理员、教务 |
| 8 | 家长端域 | 微信登录、绑定孩子、课表、余额、扣课明细、课堂反馈、请假 | 家长 |
| 9 | 消息域 | 上课提醒、扣课通知、群发通知、降级链（订阅消息→服务号→短信） | 教务（发送方）、家长（接收方） |
| 10 | SaaS 运营域 | 机构自助开通、套餐与用量计量、平台运营后台 | 平台管理员（二期） |
| 11 | 权限域 | 角色分级（管理员/教务/老师）、操作审计日志 | 机构管理员 |

## 2. 用户故事

格式：编号 ｜ 作为…我要…以便… ｜ 场景 ｜ 验收要点 ｜ 优先级 ｜ 一期/二期

## 3. MVP 边界

> 修订说明（0.1 修订版）：采用「砍法 A——先跑通生意线」。一期只保留管理端核心闭环 + 家长小程序只读三件套；课堂反馈、消息触达、请假流、退费、报表、审批、审计等一律后置二期。

### 3.1 一期（一个月内可交付）

**一期故事集合：** US-001~004、US-010、US-101、US-102、US-201~210、US-212、US-216、US-217、US-301。

**包含：**

- 管理端 Web（教务/老师/管理员三个角色登录使用）：
  - 档案：学生/家长/老师、家长-学生多对多绑定、教室档案
  - 课程：课程/班级/课时包定义（课时包支持有效期）、缴费登记（线下收款）
  - 账本：只增流水、余额快照、流水查询
  - 排课：规律排课 + 老师/教室/学生三维度冲突校验、调课
  - 签到：课堂点名/教务补录、扣课时同事务 + 幂等、缺勤扣课规则配置（US-217）
  - 交易：转班（退费、补课安排后置二期）
  - 权限：员工账号与角色分级（管理员/教务/老师）
- 家长端微信小程序（只读三件套）：
  - 微信登录、绑定/切换孩子
  - 周课表、课时余额、扣课明细
- SaaS 地基：多租户数据模型（tenant_id + RLS），运营功能不开

**明确排除（后置到二期及以后）：**

- 短信通道（降级链末级）、在线微信支付
- 平台运营后台：机构自助开通、套餐计量计费、运营看板
- 机构自有服务号授权（一期统一用平台服务号）
- 多校区、班级候补名单
- 家长端：课堂反馈查看（US-005）、上课提醒/扣课通知（US-006）、请假申请（US-007）、请假补课记录（US-009）
- 老师端：课堂反馈（US-103）、请假/调课申请（US-104）、历史反馈（US-105）
- 教务端：退费（US-211）、续费预警（US-213）、群发通知（US-214）、日报月报（US-215）
- 管理员端：经营报表（US-302）、退费/调整审批（US-303）、审计日志（US-304）、机构配置（US-305）
- 课堂反馈图片/语音附件、二维码自助签到、补课排期自助（US-106）、复杂 BI 报表、开放 API

### 3.2 一期交付判据（验收主线）

1. 教务能不碰 Excel 完成主线：建学生 → 开班 → 排课 → 缴费登记 → 签到扣课（含缺勤扣课规则）→ 流水对账 → 转班；
2. 家长在小程序看到的课表/余额/明细与后台实时一致（只读三件套）；
3. 三条红线在本期成立：签到扣课同事务且幂等；余额只能由流水变更；业务表带 tenant_id 且查询强制过滤；
4. 多租户模型预留到位（每张业务表带 tenant_id），哪怕一期只有"平台自己"一个租户在用。
