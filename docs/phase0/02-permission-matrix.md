## 0. 权限模型总则（三道闸门，缺一不可）

任何一次业务读写都必须按顺序通过三道闸门，任一闸门拒绝即整体拒绝：

1. **租户闸门（红线一）**：所有业务表带 `tenant_id`，所有查询/写入强制注入当前租户过滤，DB 层 RLS 兜底。`tenant_id` 一律由服务端从登录态解析，**绝不接受客户端传入**。
2. **角色闸门**：服务端校验角色是否在本次操作的允许角色集内；前端隐藏按钮不算防线。
3. **数据归属闸门**：在角色之上再收窄数据范围——
   - 家长：仅能命中「与当前微信号存在绑定关系的学生」的数据；多孩切换只换绑定集合内的目标，不扩大范围。
   - 老师：仅能命中「自己任教班级」的学生、名单、课次。
   - 教务/机构管理员：本租户内全量（敏感操作留痕）。
   - 平台管理员：跨租户**仅概览**，看不到任何租户业务明细。

图例：✅ 可执行　❌ 禁止　⚠️ 条件允许（条件见括号）

## 12. 越权场景清单与防线

| # | 越权场景 | 攻击方式 | 防线（落到哪道闸门） |
|---|----------|----------|----------------------|
| V-01 | 横向越权（IDOR）：家长 A 改 URL/参数里的学生 ID 看家长 B 的孩子 | 篡改请求参数 `studentId` | 数据归属闸门：每次按 `studentId` 反查「该学生是否在当前微信号绑定集合内」，不在即 403；绑定关系由教务维护，家长无法自绑 |
| V-02 | 角色伪造：伪造/重放教务、管理员 token 调接口 | 篡改 JWT 角色字段、盗用 token | 角色闸门：角色由服务端从登录态/DB 读取，不信任 token 内自声明角色；token 短时效 + 签名 + 服务端会话校验；敏感操作二次鉴权 |
| V-03 | 猜 ID：遍历学生 ID / 课次 ID 批量拉数据 | 顺序遍历自增 ID | 数据归属闸门 + 不可预测 ID（UUID/雪花）；对象级鉴权先于查询；越权请求频控与告警 |
| V-04 | 跨租户：A 机构用户访问 B 机构任何业务数据（红线一） | 改 `tenant_id`、用他租户对象 ID | 租户闸门：`tenant_id` 服务端强制注入，拒绝客户端传入；所有 SQL 强制带租户过滤 + DB RLS 兜底；跨租户访问直接命中空集 |
| V-05 | 老师越界看非任教班级学生 | 改班级 ID / 学生 ID | 数据归属闸门：老师每次查询自动叠加「任教班级」过滤，非任教班级命中空集 |
| V-06 | 教务无审批直接退费/改余额 | 直接调写接口 | 角色闸门 + 流程约束：退费必须走审批流（二期）；余额无直改接口（红线二）；课时调整强制留痕 |
| V-07 | 平台管理员下钻看租户业务明细 | 用平台账号调业务查询接口 | 角色闸门 + 字段级隔离：平台账号仅暴露概览接口，业务明细接口对平台角色一律 403 |
| V-08 | 多孩切换越界：家长切到未绑定的孩子 | 篡改切换目标孩子 ID | 数据归属闸门：切换只接受「当前微信号绑定集合内」的孩子 ID，集合外拒绝 |
